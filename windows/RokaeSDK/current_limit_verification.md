# Current-controller evidence to collect later

This is a future **read-only display/export** procedure for the operator. Nothing here was performed on the robot. Do not run `main`, enter “Waiting for PC,” launch the Python sender, jog, power on, change mode, clear alarms, identify a load, apply/reset settings or restore a project to collect evidence. Opening a local cached project is not proof of current controller settings. Establish the approved RobotAssist connection procedure before obtaining live displays.

Capture the complete page, units, all six joint columns, enable flags, normal/reduced columns and current robot identity. Include capture date/time and whether the display is live or cached. Exact UI wording may differ in RobotAssist 5.0.11; the local xCore V3.0_B manual documents the concepts, including §11.3.2 Joint position and §15.4.16.22–23 acceleration/jerk. If a page requires changing mode or applying values, stop at the display and record that limitation.

| Evidence | Screenshot/export values required |
|---|---|
| Physical identity and About/controller information | Nameplate robot model and serial; controller model/serial; full firmware/build; RobotAssist version. Confirm CR7-C versus another CR7 variant. Cached key XMC7-R850-W7G3B4C-S5 maps to CR7-C but is not live proof. |
| Current connection and project | Connected robot identity, displayed operating/power state, selected project, running/stopped state of all tasks, current control source and RT/RCI availability. Record `Artist_movement_finish` without running it. Capture status only. |
| Safety → Joint limits → Joint position | Enable state; lower/upper limits for joints 1–6 in both normal and reduced modes; units; active normal/reduced state and its selection source. Capture all columns even when inactive. |
| Soft limit page | Enable state and normal/reduced lower/upper values for all six joints. If separate from safety joint-position limits, collect both pages. Do not infer one from the other. |
| Active safety configuration | Safety checksum/validation state; active limit set, reduced-mode input/state, enabled joint speed/torque/power limits and values; relevant virtual walls/workspace restrictions, TCP speed/force/power limits and stop conditions. Record unavailable fields explicitly. |
| Robot/motion parameters | Current JOINT_MAX_SPEED, JOINT_MAX_ACC, JOINT_MAX_JERK, units, jerk-enable flags, mode-specific reductions and overrides. Determine separately whether these constrain RT jointPosition, not only RL planning. Do not issue SetRobotJointsMaxAcc/Jerk or a reset. |
| Tool/workobject/load | Selected tool and workobject names/IDs; TCP translation/orientation and units; load mass, center of mass, inertia and associated frames; load enabled state; any external/end-effector loads. Export existing numbers only; do not run load identification or calibration. |
| Calibration and joint convention | Installed kinematic/calibration version and enable state; zero-offset convention and turn counts; displayed joint values with units; SDK q_m/JointPosition joint order/sign/offset mapping evidence. Do not test mapping by moving. |
| SDK compatibility and ownership | Vendor confirmation for exact SDK archive/firmware; whether passive state subscription needs any mode/power change; state-read thread safety; what construction/destruction/disconnect and process/network failure do to independent RL tasks. |

Where available, use a controller-to-PC **read/export/backup** operation that does not write to the controller; retain the original export, its timestamp and SHA-256 beside screenshots. Do not use download-to-controller, restore, synchronize-write or Apply. If direction/side effects are unclear, collect screenshots only. Redact credentials if present, while preserving the technical values above.
