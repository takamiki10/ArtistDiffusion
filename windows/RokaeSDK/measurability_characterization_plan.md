# Prospective characterization before R/D collection

No stage has been run. Keep path_0001/path_0003/path_0006 and the six R/D files unchanged. Characterization must precede any physical measurability threshold and all R/D outcomes. A small digital variation is not an encoder-accuracy specification, and controller Cartesian output is not an independent external metrology measurement.

## Stage A: stationary acquisition

First resolve the connection gates in the architecture/report and implement/review the passive backend. Use one verified owner, no running drawing task or other command source, and an operator-confirmed stationary robot in its existing approved state. No motion, power, mode, alarm, tool or safety command is allowed. If subscriptions require a state change, this passive protocol is blocked; do not make the change as part of capture.

Propose five 60-second records at requested 1 ms subscription, separated by recorded session boundaries, after a recorded stable observation period. This duration is a prospective choice, not evidence that the system is stationary. Capture q_m and supported dq_m/pos_m; read status separately with its bracket and a fixed recorded policy. Request q_c only when its meaning is confirmed in that mode. Record payload size, callback/read timing policy, OS/clock, SDK versions, controller settings, tool/load, temperature/time since power-up where available, and all error events. Never fabricate a controller clock or frame counter.

Report read-end interval median, p95, p99, maximum, histogram, timeout counts, duplicate/backward timestamps, per-read duration and writer/queue diagnostics. Report host gaps greater than 1.5× and 2× nominal period as gap diagnostics, not exact controller-frame loss. If an actual source counter is unavailable, state that controller loss/freshness cannot be fully identified. Compare observed cadence with the request; do not label all recorded rows “1 kHz” from the requested rate alone.

For each joint report distinct binary values, smallest nonzero observed differences and their histogram, stationary mean/SD, median absolute deviation, peak-to-peak range, time trend and autocorrelation/effective sample size. Do not treat thousands of correlated readings as independent repeats. For pose report translation and SO(3) angular variation in the verified frame. If values remain constant, report an upper bound constrained by observed digital output, not zero physical noise. Relate host timing uncertainty to velocity only in later motion data, not by pretending stationary data measure tracking.

Before Stage B, freeze acquisition acceptance rules, sampling/alignment method and fault handling using Stage A evidence. Required structural rules: all required q values finite and valid; no raw corruption, queue loss, writer failure or nonmonotonic/duplicate host times; complete metadata and verified mapping. Freeze a numeric timeout/gap/deadline budget after Stage A and before Stage B; an unfilled budget prevents progression. Keep rejected sessions and reasons. No event-free synthetic test substitutes for these observations.

## Stage B: separately authorized neutral repeatability

Prepare a neutral motion through an independently reviewed safe region, with reviewed approach/hold/return, tool/load, limits, clearance and dynamics. It must not equal any of the six experimental commands and must be selected from engineering workspace coverage and representative speed/acceleration requirements, without evaluating which trajectory favors D. Its amplitude/duration cannot be chosen safely from the present files alone. Review and freeze its full file/hash, interpolation, command timing, expected envelope, repetitions and abort policy before separate operator motion authorization. A generic motion example or SDK read-state demo must not stand in for that approval.

Prospective design: 20 pairs of repetitions of the same neutral command across two independently documented sessions (10 pairs per session). Use the same reviewed start procedure and timing for each repeat, balanced order/labels and recorded inter-run conditions. Both members command the identical neutral reference; labels are arbitrary and contain no diffusion condition. Session is the replication block. Record actual timing and tracking under the same acquisition configuration planned for R/D; target-versus-measured comparisons alone cannot verify SDK filter bypass.

Analyze paired differences of predeclared trial metrics at the trial/pair level, not as independent per-sample tests. Suggested primary Cartesian metric is RMS position error against the fixed host reference under a verified model/TCP; retain joint RMS/max tracking and timing error as secondary diagnostics. If kinematic/model/TCP uncertainty prevents a defensible Cartesian metric, freeze a joint-space metric instead before Stage B, and state that Cartesian eligibility remains unresolved. Do not change metrics after observing R/D results.

Freeze alignment independently: use documented start events and host uncertainty, not per-trial error-minimizing shifts or dynamic time warping. Use the same prospective quintic reference in analysis, with separate recorded host-versus-controller time uncertainty. The unchanged Jetson evaluator's linear/previous interpolation is not yet adequate for this candidate. Stage B must demonstrate repeatability and temporal provenance before adopting it.

## Freeze the eligibility rule

Before Stage B, register the formula: for the chosen primary metric, estimate the 95th percentile of the absolute within-pair neutral repeat differences and a one-sided 95% confidence upper bound using a predeclared session-block bootstrap (10,000 replicates, fixed seed 20260913). With only two sessions, cross-session uncertainty is weakly estimated; expand the neutral characterization with a preregistered additional-session design if the bound is unstable, before collecting R/D. Never let extra R/D observations decide that expansion.

The eventual eligibility threshold is the larger of that conservative neutral-repeatability bound and a separately justified metrology/model/timing uncertainty floor, in the same metric and units. The floor must include joint readout, TCP/model and timing provenance; do not derive it from manufacturer repeatability alone. No numeric threshold is available now. If uncertainty cannot be bounded, record “measurability unresolved,” not a zero threshold. This is an eligibility screen, not a guarantee of statistical power.

After neutral characterization, freeze a signed/versioned protocol containing dataset hashes, complete threshold calculation, confidence method, exclusions, metric, reference convention, alignment, controller/settings/tool state and planned R/D trial count/order/statistical analysis. Any required benchmark-analysis extension lives outside the immutable handoff package and is reviewed before collection. Only then apply the frozen eligibility rule to planned effects. Do not derive the threshold from outcomes on paths 1, 3 or 6, choose targets based on observed R/D gains, or silently replace a failed path. Changed settings or acquisition invalidate transfer of the characterization and require a new prospective review.
